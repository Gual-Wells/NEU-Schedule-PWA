# NEU Schedule PWA

一个面向手机快速查看的个人课表 PWA。周表和日程把课程与健身房开放时间放到同一张时间图上；健身页独立保存实际训练记录。

v23 功能版固定在 [`73e873906896e41f0db4b047e013cf2300622465`](docs/BASELINE_V23.md)；各模块的设计、验证与可复用经验见 [项目经验报告](docs/PROJECT_EXPERIENCE.md)。

界面使用 2008 年前后 Web 2.0 课表的视觉语言：蓝灰色工具栏、轻微高光、方形标签页和清晰的表格边框；保留手机安全区与响应式布局。

## 当前产品结构

- `周表` 是默认主视图：手机竖屏一次看到完整 7 天，不再横向自动滚动隐藏周一/周二。
- 横轴是周一到周日，纵轴是 `00:00–24:00` 连续真实时间；仅标两端，节次与健身房时刻标在各自位置。
- 课程使用稳定颜色块，块内标出所跨节次；左侧每节都显示起止时间，课程位置、高度与节次采用同一真实分钟坐标。
- 健身房开放时间作为背景铺在对应日期列中，按连续日期交替使用两种浅色，跨周相邻日期也保持区别。
- 健身房开放/关闭边界若不与课程节次边界重合，会显示绿色虚线和时间值；与课程边界重合时使用绿色实线。
- 当前时刻在本周今天显示红线。
- `日程` 是从当日课表提取的单日时间图：顶部时钟与当前/即将事件，下面是真实时间纵轴、健身背景、课程块和随分钟更新的进度线。
- **所有课程默认已翘**：课程仍在原位置，以弱化样式显示，不占用个人健身时间。仅今天的课程可以手动逐节恢复上课（重新占用时间、切换正常上课提醒），支持再次翘课或一键恢复今日全部课程。次日清空的是手动恢复例外，课程重新默认已翘；历史和未来的课程沿用只读限制。
- `健身` 是第三个主视图：开始/结束训练、实时计时、本周/本月摘要、每周趋势、最近和全部训练。训练以起止时间持久化，统计由训练记录计算。课程状态不会自动开始或结束健身。
- 教学周支持左右按钮、周标题跳转和左右滑动；非今天/非本周时提供“回到今天”。

v31 已取消「安排组会」的独立入口，新组会统一从「事项」按活动手动添加或图片导入。已有组会继续查看、结束或取消，保留原有参数和历史：前三小时实线表示预计占用，后两小时虚线表示弹性窗口；默认生效、不提供翘课，点击「结束组会」认定实际结束（最多计五小时）。组会参与可健身时段扣除，且不改变原课程或健身记录。详细语义和非破坏性部署步骤见 [`docs/GROUP_MEETINGS.md`](docs/GROUP_MEETINGS.md)。

## 图片事项与每日汇总（v33）

v30 支持同一导入任务提交 1–8 张图片，合计最多 20 MiB：可分次选图、预览、排序和删除，草稿在刷新后恢复；重试只补传缺图，全部齐全后才联合识别。重复通知合并，矛盾时间留待核对，候选与已入表事项都保留来源图号。具体约定见 [多图协议](protocol/AGENDA_MULTI_IMAGE.md) 和 [单项审核与反馈](protocol/AGENDA_SINGLE_REVIEW.md)。

顶部「事项」可上传通知截图，识别活动、DDL、地点及原文证据；一次申请只生成一份事项，多图中的干扰信息由模型结合上下文筛除。支持结合截图日期和当前时间合理推断；只有日期时按全天预留。后续补充、变更图片仍从同一入口提交，识别为已有申请时合并更新原事项。周/日视图中非课程事项共享右半列，重叠课程保留左半列，点击右侧展开全部安排。审核只显示固定生成结果；需要调整或时间有疑点时，针对原申请提交文字反馈，由模型返回改写后的单项结果，再整体确认入表，也可以手动添加。新活动默认向后三小时（实线一小时、虚线两小时），DDL 向前三小时（虚线两小时、实线一小时）。明确活动结束时间优先。所有窗口均占用健身时间；进入窗口后，即使跨日或超过预计结束，仍须点击「DDL 达成」「结束活动」或「结束组会」才释放。组会保留原有 3+2 小时参数，超过五小时也不能自动释放占用。

每日北京时间 07:00 和 22:00，云端汇总未来滚动 72 小时的未完成活动、DDL、组会及过去尚未确认事项；长清单可从通知打开完整页。课程与健身原提醒保留，组会不再单独推送。原通行密钥和推送订阅继续使用。

识别由本机登录的 ChatGPT Codex CLI 执行，本机离线时队列等待；每日汇总在云端运行。没有任务时不调用模型。不启用 R2、不新增付费 API；使用现有 D1 暂存最多 50 MiB 图片，72 小时清理。协议、接口和部署见 [protocol/AGENDA.md](protocol/AGENDA.md)。

## 移动端布局

页面本身不滚动。顶部课表、周切换和视图切换保持稳定，周表时间图、日程时间图和健身页分别在自己的区域内滚动；进入健身页时隐藏教学周选择器。布局同时使用 `100dvh` 和 safe-area 环境变量。

## 数据

- `2026-09-24 = 第 4 周`
- 第 1 周周一：`2026-08-31`
- 班级信息依据用户提供的《研究生选课》PDF；只填写其中明确标注的班号，未标班号的课程保持为空。
- 健身房开放表来源：用户提供的 `2026-09-04 动态更新`照片。

## PWA

页面仍是纯 HTML / CSS / JavaScript，无界面框架或广告；通行密钥交互使用随站点部署的 SimpleWebAuthn 浏览器库。正式 PWA 与 API 同域部署在 Cloudflare Pages；旧 GitHub Pages 地址已停用，返回 404。

静态资源使用版本化 URL；Service Worker 版本为 `neu-schedule-v33`，导航优先网络、离线回退缓存，且不缓存认证或数据 API。主屏幕 PWA 禁止双指和双击页面缩放，单指滚动保留；登录密钥输入框使用 16px 字号，避免 iPhone 点按后自动放大。用户主动切换视图后，迟到的云端同步不会把标签切回。测试推送有 10 秒冷却，按钮显示等待时间；正式课程与健身提醒不受该冷却限制。部署前检查数据约束、日程状态切换、健身记录、推送计划、放假调休和登录边界。

日程页的「放假／调休」可将本学期一天或连续多天设为放假，取消当天课程与课程提醒，健身房开放背景照常显示。调休先选原本无课的目标日，再选有课的来源日；来源日课程整体挪到目标日，节次、地点、教师及备注不变，提醒改按目标日发送。调休和放假可逐条撤销，安排保存在 D1 并跨设备同步。原始周课表不被改写。

课程、节次和健身房开放表以 Cloudflare D1 为运行时权威。新站点地址为 `https://neu-schedule-push-api.pages.dev/`。首次登记需后台五分钟窗口与单独的初始化密钥；之后仅用唯一通行密钥登录。会话保存在同域 HttpOnly Cookie，最长 90 天，打开页面无需每次验证。登录后才读取云端课表。

训练记录、当天手动恢复的上课例外和视图偏好也同步到 D1。旧设备首次登录会导入本机训练记录；之后本机仅保留离线缓存与待补传操作。训练记录可从健身页导出 JSON 备份并导入。离线修改会在再次联网、打开页面或手动同步时上传。恢复/翘课只接受当天课程，后端每天清理过期状态；训练记录长期保存。旧显式翘课数组不再作为新状态的权威；新记录采用 `{mode:"default-skip-v1",ids:[...]}`，存于原 D1 JSON 列，无需数据库迁移，但前端与 Worker 必须一起部署。旧版 `gymSessionDate` 只有开放段结束时间，无法还原真实开始时间，因此不会伪造为历史训练。

登录、登记窗口、会话和后台重置规则见 [`worker/AUTH_DESIGN.md`](worker/AUTH_DESIGN.md)。初始化密钥只授权在已打开的窗口内登记，不能读取课表。提醒订阅令牌也不能单独读取数据或修改推送计划。课程表无网页写入接口，后续课程和开放表调整需通过受控的 D1 迁移发布。如曾从旧站导出训练记录，可在新站点导入；浏览器本地存储不会跨域自动迁移。公开仓库历史可能仍包含旧版课表数据。

## 后台提醒

页面的“提醒”按钮可开启 Web Push。iPhone 需要先把新站点加入主屏幕，并从主屏幕打开；登录后点击按钮申请通知权限，无须配对码。开启后可发送一条测试通知，也可随时关闭并删除服务端订阅。

Worker、每分钟 Cron、D1 数据库和部署命令见 [`worker/README.md`](worker/README.md)。页面通过同域 API 同步提醒；Worker 负责保存与投递。翘课、撤销、健身状态变化以及重新打开页面会重同步计划；跨日清空手动恢复例外也会重同步。默认已翘课程的后续提醒仍保留原时刻，但文案改为“已翘课程”。推送数据采用 WebKit Declarative Web Push 格式，Service Worker 同时处理传统 Web Push 与点击打开日程。

推送属于尽力投递，不是保证准点的闹钟。设备需保留通知权限与有效订阅；更换站点、设备或重装 PWA 后需要重新开启。初始化密钥和 VAPID 私钥只保存在 Cloudflare Secret 与仓库外备份，不进入公开仓库。

收到推送时，支持 Badging API 的主屏幕课表图标会显示一个未查看标记；打开课表后清除。解锁使用手机时通知横幅是否持续显示由 iPhone 的“设置 → 通知 → 课表 → 横幅风格”控制；如果设备提供“持续”选项，用户可自行选择。持续横幅不等于锁屏实时活动。
