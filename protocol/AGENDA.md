# 图片日程与健身占用协议

业务协议版本 1，2026-10-18，时区 Asia/Shanghai。v30 增量启用[多图附件协议 2](AGENDA_MULTI_IMAGE.md)。

活动以开始时刻为锚点，缺少结束时刻时，开始后一小时实线、其后两小时虚线，总跨度三小时。图片明确的结束时间优先，不能默认为一小时。DDL 以截止时刻为锚点，前三小时开始占用，前两小时虚线，最后一小时实线。只有日期、相对日期缺少可靠锚点或时间有歧义的候选必须人工补全，不自动猜测时刻。

所有实线与虚线窗口均挤占健身时间。窗口尚未开始时，以预计窗口投影未来占用；进入窗口后，未确认事项保持开放占用直到用户确认。预计结束或截止不是自动释放条件，跨日仍可找到并确认。活动须开始后才能结束；DDL 可以提前达成。确认只释放确认之后的占用，不伪造实际投入时长。取消保留审计状态并释放安排。

组会沿用三小时实线、两小时虚线和最长五小时的认定记录；健身占用释放以真实点击的 confirmedAt 为准，未点击不得因五小时上限自动释放。结束认定 endAt 与释放确认 confirmedAt 含义不同，不覆盖历史。

日程允许活动和 DDL 重叠，显示冲突而不移动真实锚点。组会自身的新增重叠约束沿用已有规则。原课程、默认翘课、当天恢复上课、放假调休、训练记录与通行密钥语义保持。

每日北京时间 07:00 和 22:00，从 D1 即时生成未来 72 小时全部未完成活动、DDL 和组会的汇总；过去仍未确认的事项另保留在待确认集合中。每事项只列一次，完成和取消后不再进入后续汇总。空集合也生成无安排汇总。完整结果持久保存，推送过长时明确标注总数及完整页入口。两次时段互不按内容去重。活动、DDL 和组会不再产生逐项推送；课程与健身提醒保留。旧客户端上传不得覆盖汇总或重新启用组会逐项推送。

图片导入：每批 1–8 张，合计最多 20 MiB；单张 PNG/JPEG/WebP 最大 5 MiB，像素最大 1600 万；暂存在已有 D1 的 256 KiB 分片，最多保留 72 小时，图片总存量最多 50 MiB。逻辑到期立即禁止读取，Cron 删除分片。图片、来源和候选仅登录用户及持有当前任务租约的独立运行器可读，Service Worker 不缓存业务接口。浏览器重编码剥离图片元数据。

新批次先处于 uploadState=draft，仅上传到齐且显式 submit 后才进入 ready。导入状态 queued → running → review → applied；failed 由用户重新上传重试，尚未应用可取消。领取代次和租约绑定结果回传，过期分析不自动重新启动。输出先写本机 pending 产物，再校验并原子保存；上传失败重用已有分析。模型只输出候选，不能执行日程写入或读取业务发布凭据。含不确定字段的候选保留原图证据、问题和空值，用户可编辑、排除后应用。

写入采用请求 ID 与内容摘要幂等，重复内容请求返回原结果；同 ID 不同内容拒绝。导入应用以 revision 在 SQL 事务内校验，单向完成与取消不能被旧设备重新打开。确认时间由服务端校验，离线确认进入待补传队列；云端回读覆盖本地前必须叠加尚未发送的确认操作。

接口、运行器与部署细则见 [AGENDA_API.md](AGENDA_API.md)。
