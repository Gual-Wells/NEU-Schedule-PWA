# 宽泛时间、追加识别及半列布局（v33 / 提取协议 4）

模型理解时联合使用消息日期、星期、相对日期、同组截图的年月周次及上传参考时刻。近期聊天没有消息日期时允许将参考日期作为默认锚点，inference 明确说明推断依据，不能仅因缺少完整年月日而拒绝生成。背景通知可以提供年份和周次参照，但不能将背景活动的具体时刻移到目标事项。对象确定而地点等细节缺失时可留空，不用问题阻塞生成。

只明确日期，或只知早晚而具体时刻不明时，使用 dateStart 与 dateEnd（YYYY-MM-DD，含首尾，单日相同），localTime/localEnd 为 null。活动与 DDL 都覆盖日期的 00:00 至末日次日 00:00，整段实线；不存在默认三小时。内部 deadline anchorAt 为末日结束边界，activity 为首日开始；界面和汇总始终显示真实日期与“全天”，不把内部午夜边界显示为另一天的截止日期。具体时间明确时 dateStart/dateEnd 为 null，继续使用既有精确时刻及三小时默认窗口。推断依据与原文证据分开保存；非空 question 不再阻断有效日期的宽泛结果。整日窗口仍挤占健身，进入窗口后直到显式完成或结束才释放，不能自动在午夜释放。

后续通知、补图、改期、追加要求仍用同一上传入口。claim protocol:4 返回 knownApplications：持久保存的候选申请 ID/版本、已确认事项或未确认生成结果。模型输出 relation new 或 update；update 只能引用该快照中存在的 applicationId 和 item.id，并说明同一事项的对应线索。同名但独立发生的不同周次事项不能按名称盲目合并。更新输出必须是一份合并后的完整结果，保留未更改的时间、地点和要求；追加材料不能把已有明确时间退化为全天。

确认阶段进行事务内版本核对，关联目标变化时返回 409，要求基于新版本重新识别。agenda_application_items 以原申请为稳定身份绑定唯一事项；新申请通过 canonical_id 指向它，更新同一事项 ID。原申请尚未入表时，补全后的确认只创建一份安排，并使旧版本不能再确认。已入表时新结果确认前旧安排继续生效，确认后原位更新；完成和取消不能重开。原申请、各次补充及当前图号都保留在 agenda_item_sources；source_import_id 指向最近一次确认使用的图片。新的反馈可通过任意关联申请发起。

周视图与日视图将活动、DDL 和历史组会统一投影到右半列。重叠的课程缩到左半列并保留课程操作入口；健身房开放背景不变。非课程区按重叠连通组建立点击区域，再按时间边界切片；同一切片内 N 个事项各得右半列的 1/N，事项结束或新增时重新分配。点击该区域弹出包含所有关联事项的完整清单，可进入原事项或旧组会操作。到午夜裁剪，不让全天项目溢出到相邻日期。

部署应用 0014 增加日期、推断、上下文、关联和来源历史字段；旧精确时间数据无需迁改。运行器能力 4 隔离旧协议，旧在途结果保持兼容。新的本机运行目录固定版本，保留仓库外模型/推理配置及现有通行密钥、推送设备。没有新增外部服务或订阅，推理仍消耗现有模型配额。
